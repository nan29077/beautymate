## 4. 예약 → 결제 → 확정 플로우 연결 ✅

### 문제
점집 예약 플로우(`/shop/[slug]/book` → BookingFlow)는 예약 생성 후 결제 없이 "상담사 확정 대기"로 끝났음 (PG 연동은 장바구니 `/checkout` 전용).

### 조치
- `POST /api/payments/prepare` (신규 통합 진입점) — 예약 소유권·상태 검증 후 사용 가능한 결제 수단 목록 반환: seedpay(카드, `launch?full=1` 리다이렉트) / ongi(간편계좌, 기존 prepare 재사용) / mock(개발용).
- **Mock PG** (개발 전용, `NODE_ENV=development` 또는 `MOCK_PG_ENABLED=true`에서만 활성):
  - `/pay/mock` 결제창 — 서버에서 HMAC-SHA256 서명한 성공/실패 페이로드 발급
  - `POST /api/payments/mock/webhook` — **시그니처 검증**(timingSafeEqual + 5분 유효) → 멱등 → CONFIRMED/COMPLETED → 세션 생성 → 알림톡·인앱 알림 (실 PG 콜백과 동일 처리)
  - `src/lib/mockPg.ts`, PaymentLog에 `mock`/`webhook` 타입 확장
- BookingFlow에 `pay` 단계 추가: 예약 생성 → prepare → 결제 수단 선택 → PG 결제창. PG 미설정/실패 시 기존 "확정 대기" 흐름으로 폴백 (기존 동작 보존).
- 완성된 흐름: 예약(PENDING) → prepare → PG 결제창 → 웹훅/콜백 → CONFIRMED + 세션 자동 생성 + 상담사 알림톡 + 고객 인앱 알림 → `/checkout/complete`.
